# 문의 접수와 알림 연결 계획

Goal: 기존 상담 폼의 실제 접수, 관리자 전용 저장, 이메일 알림을 검증한다.
Architecture: Next.js 정적 사이트 → Supabase Edge Function → 기존 inquiries + 알림 outbox → Resend 템플릿. 계정·CMS 활성화는 다음 단계.
Spec: 사용자가 4단계 실행 및 Resend 공식 설치 절차를 요청. 수신자는 기존 공식 이메일 osmu_studio@naver.com. 기존 상담 필드 유지, 서비스 복수 선택, 동의·오류·중복 방지 추가.

- [x] 발신 도메인 notify.osmu-studio.com을 도쿄 리전에 등록하고 승인된 DNS 4개를 추가한다. 추적·수신 기능은 끈다.
- [x] 검증 함수와 테스트를 작성한다. 필드 길이, URL 프로토콜, 동의, 서비스 허용목록, 허니팟, 동일 요청 재시도를 검사한다.
- [x] inquiries 기존 데이터를 보존하고 서버 전용 접수 RPC와 알림 outbox를 추가한다. 공용 직접 삽입을 닫고 기존 관리자 읽기 권한을 유지한다.
- [x] 서버에서만 메일을 발송한다. 저장과 알림 대기열 생성은 원자적으로 처리하고, 발송 실패 시에도 접수 성공을 유지한다. 동일 접수의 이메일에는 같은 멱등키를 쓴다.
- [x] 실제 연결 준비가 완료되기 전까지 운영 미리보기는 유지한다. 개인정보 안내와 동의에는 실제 저장 위치·항목·보관·삭제 정책을 반영한다.
- [x] 잘못된 입력, 비관리자 조회 차단, 중복 제출, 발송 실패, 정상 접수를 검증한다. 데스크톱·모바일과 운영 배포, 네이버 메일 전달을 각각 확인한다.

Review focus: 저장 성공 후 메일 실패; 재시도 중복; 공개 테이블 직접 삽입; 개인정보가 분석 이벤트나 메일로 불필요하게 유출; 320px 모바일 폼.
Ruling: 기존 서비스 사양과 단계별 실행 승인을 바탕으로 본 세션에서 직접 구현한다. 별도 CMS 기능이나 마케팅 추적은 켜지 않는다.

검증 상세: docs/contact-operations.md. 최종 운영 도메인 재검증은 배포 후 수행.
