# 2단계 — 재구축 후 URL·검색 기본 설정 정리

점검일: 2026-11-08 (Asia/Seoul)

## 범위와 결정

- 공개 페이지 47개, 관리자 1개, 이전 사이트맵과 커밋 365b750의 실제 프로젝트·서비스 경로를 비교했다.
- 사용자 선택: 종료된 콘텐츠는 삭제하고, 현재 대응 페이지가 있는 구형 주소만 이동 연결을 유지한다.
- 주소 대응표: `lib/legacy-routes.json`. aliases 18개, retired 58개.
- 기존 프로젝트 원본과 작업 데이터는 삭제하지 않는다. 변경 대상은 공개 정적 사이트의 경로와 빌드 결과물이다.

## 확인한 문제와 수정

1. 기존 `studio.html`, `service.html`, 웹사이트 서비스 주소에 최종 목적지 연결을 추가했다.
2. 이동 안내의 noindex를 제거하고, 목적지 canonical과 즉시 이동을 일치시켰다. 관리자 이동 주소는 noindex/nofollow를 유지한다.
3. 브라우저 이동 시 UTM과 본문 위치를 보존한다. JavaScript를 사용하지 않는 경우 즉시 meta refresh와 링크로 이동한다.
4. 대체 콘텐츠가 없는 종료 주소는 HTTP 200 안내문 생성을 중단했다. 실제 GitHub Pages 404 응답과 사용자 안내로 처리한다.
5. 기존 홈페이지에서 확인한 Google·네이버 소유 확인 태그를 복구했다. 태그 복구와 콘솔의 소유 확인 성공은 별도다.
6. 데이터 측정 서비스의 `#engagements` 대상 누락을 수정했다.
7. 루트 레이아웃의 기본 index 지시가 404의 noindex와 충돌하지 않도록 제거했다. 공개 페이지와 관리자의 기존 개별 robots 설정은 유지한다.
8. 404 안내에 서비스·인사이트 이동 경로를 추가하고 모바일 버튼 간격을 정리했다.
9. 배포 전 검사에 본문 앵커, OG·Twitter·글 구조화 데이터 이미지, 소유 확인 태그, 구형 주소 목적지·연쇄 이동·UTM 보존·종료 주소 404 조건을 추가했다.

## 범위와 한계

- GitHub Pages 정적 호스팅이므로 경로별 이동은 HTTP 301이 아닌 즉시 HTML 이동이다. Google은 즉시 meta refresh도 영구 이동 신호로 설명한다. 서버의 301/308이 가능한 경우 그 방식이 우선이다.
- HTTP/www/기본 GitHub 도메인 → 대표 HTTPS 주소는 현재 실제 301로 작동한다.
- 이 검증은 검색 콘솔의 색인 성공·검색 순위·AI 인용 확인이 아니다. 검색 콘솔 등록·수집 확인은 다음 단계다.
- 기존 계정, 문의 접수, CMS, 분석·광고 연결은 이번 단계에서 활성화하지 않는다.
- 운영 배포 후 결과는 별도의 `setup-step2/after.json` 점검 기록으로 보관한다.
